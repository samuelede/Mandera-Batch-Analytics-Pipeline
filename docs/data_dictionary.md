# Data Dictionary — Mandera Analytics Pipeline

This document describes all entities, fields, and business definitions
used in the Mandera Analytics batch pipeline.

All table names below are sourced from `config/settings.py` —
`RAW_TABLES` and `STAGING_TABLES`. If a table is ever renamed, update
`settings.py` first; every script in `extraction/`, `transformation/`,
`validation/`, and `maintenance/` derives its table names from there.

---

## Schema Overview

| Schema | Purpose |
|---|---|
| `raw` | Landing zone for records extracted from MongoDB Atlas. Preserved before transformation. Tables suffixed `_raw`. |
| `staging` | Analytics-ready tables produced after cleaning and validation. Tables suffixed `_clean`. |
| `monitoring` | Pipeline observability: batch counts, variance, and quality checks. |

---

## Data Quality Simulation

Every batch is generated with deliberately injected data quality issues,
controlled centrally via `DATA_QUALITY_PROFILE` in `config/data_quality.py`.
This is what gives the validation layer something real to catch.

Two mechanisms are used:

1. **`introduce_bad_data()`** — applied per-record, inside each `faker_*.py`
   generator. Injects field-level issues (nulls, invalid values, domain
   violations) at the rates defined per entity below.
2. **`inject_duplicates()`** — applied once per batch, after all records
   are generated. Walks the batch and probabilistically overwrites a
   later record's non-key fields with an earlier record's fields,
   simulating the same real-world entity being re-submitted under a new ID.
   The duplicated record keeps its own primary key — it is not a true PK
   collision, since `raw.*_raw` tables enforce `(id, batch_id)` uniqueness.

| Entity | Injection rate | Field/Issue |
|---|---|---|
| Customers | 0.4 | `missing_email_rate` — email set to `None` |
| Customers | 0.4 | `invalid_email_rate` — email set to `"invalid_email@@"` |
| Customers | 0.4 | `missing_city_rate` — city set to `""` |
| Customers | 0.4 | `duplicate_rate` — record duplicated from an earlier one in the batch |
| Products | 0.42 | `missing_name_rate` — `product_name` set to `None` |
| Products | 0.4 | `invalid_price_rate` — `unit_price` set to `-1.0` |
| Products | 0.4 | `zero_price_rate` — `unit_price` set to `0.0` |
| Products | 0.4 | `category_mismatch_rate` — `category` reassigned to an unrelated value |
| Products | 0.4 | `schema_drift_rate` — adds `legacy_discount_code`, a field not in the staging schema |
| Products | 0.3 | `duplicate_rate` — record duplicated from an earlier one in the batch |
| Orders | 0.4 | `missing_product_rate` — `product_id` set to `None` |
| Orders | 0.4 | `invalid_amount_rate` — `total_amount` set to `None` |
| Orders | 0.4 | `negative_amount_rate` — `total_amount` set to a negative value |
| Orders | 0.4 | `invalid_status_rate` — `order_status` set to `"unknown_status"` |
| Orders | 0.4 | `duplicate_rate` — record duplicated from an earlier one in the batch |

> **Why this matters for variance monitoring:** with multiple overlapping
> bad-record categories plus duplicate injection, raw → staging row count
> variance regularly exceeds the default 5% threshold in
> `validate_batch_counts.py`. A `WARN` status under this generator profile
> is expected behavior, not necessarily a pipeline defect — it reflects
> the proportion of records the transformation layer correctly filtered out.

## raw.customers_raw / staging.customers_clean

`settings.RAW_TABLES["customers"]` → `raw.customers_raw`
`settings.STAGING_TABLES["customers"]` → `staging.customers_clean`

| Field | Type | Description | Notes |
|---|---|---|---|
| `customer_id` | TEXT | Unique customer identifier (UUID) | PK (with `batch_id`); generated by Faker |
| `batch_id` | TEXT | Pipeline batch run identifier | Generated by `settings.generate_batch_id()` |
| `first_name` | TEXT | Customer first name | |
| `last_name` | TEXT | Customer last name | |
| `email` | TEXT | Customer email address | May be `None` or `"invalid_email@@"` in raw (injected); normalised to lowercase in staging; null/invalid rows dropped before staging |
| `phone` | TEXT | Contact phone number | |
| `city` | TEXT | Customer city | May be `""` in raw (injected) |
| `country` | TEXT | Customer country | |
| `registration_date` | TEXT / DATE | Date customer registered | Cast to DATE in staging |
| `is_active` | BOOLEAN | Whether account is active | Defaults to TRUE in staging if null |
| `segment` | TEXT | Business segment | Values: `retail`, `wholesale`, `online`; null/empty → `unknown` in staging |
| `transformed_at` | TIMESTAMPTZ | When staging record was written | Staging only |
| `loaded_at` | TIMESTAMPTZ | When record was loaded into PostgreSQL | |

**Transformations applied (`transform_customers.py`):** drop rows with
null `customer_id` or `email`; lowercase + strip `email`; replace empty
or null `segment` with `unknown`; cast `registration_date` to `DATE`;
default null `is_active` to `False`.

## raw.products_raw / staging.products_clean

`settings.RAW_TABLES["products"]` → `raw.products_raw`
`settings.STAGING_TABLES["products"]` → `staging.products_clean`

| Field | Type | Description | Notes |
|---|---|---|---|
| `product_id` | TEXT | Unique product identifier (UUID) | PK (with `batch_id`) |
| `batch_id` | TEXT | Pipeline batch run identifier | |
| `product_name` | TEXT | Product display name | May be `None` in raw (injected); null rows dropped before staging |
| `sku` | TEXT | Stock-keeping unit code | Null rows dropped in staging |
| `category` | TEXT | Product category | Drawn from `settings.PRODUCT_CATEGORIES`; normalised to title case in staging |
| `unit_price` | NUMERIC(12,2) | Selling price per unit (USD) | May be `-1.0` or `0.0` in raw (injected); rows with price ≤ 0 dropped before staging |
| `currency` | TEXT | Price currency | Default: USD |
| `stock_quantity` | INTEGER | Units available in stock | |
| `supplier` | TEXT | Supplier company name | |
| `cost_price` | NUMERIC(12,2) | Cost per unit | Computed as 60% of `unit_price` at generation time |
| `is_active` | BOOLEAN | Whether product is listed | Defaults to TRUE in staging if null |
| `legacy_discount_code` | TEXT | Schema-drift field simulating an upstream source change | **raw only** — dropped before writing to staging; `staging.products_clean` has no column for it |
| `transformed_at` | TIMESTAMPTZ | Staging write timestamp | |
| `loaded_at` | TIMESTAMPTZ | PostgreSQL load timestamp | |

**Transformations applied (`transform_products.py`):** drop rows with
null `product_id`, `sku`, or `product_name`; drop rows with
`unit_price <= 0`; title-case `category`; impute null `cost_price` at
60% of `unit_price`; **drop `legacy_discount_code` entirely** before
writing to staging, since it represents an unplanned upstream field
that the warehouse schema does not (yet) accommodate.

## raw.orders_raw / staging.orders_clean

`settings.RAW_TABLES["orders"]` → `raw.orders_raw`
`settings.STAGING_TABLES["orders"]` → `staging.orders_clean`

| Field | Type | Description | Notes |
|---|---|---|---|
| `order_id` | TEXT | Unique order identifier (UUID) | PK (with `batch_id`) |
| `batch_id` | TEXT | Pipeline batch run identifier | |
| `customer_id` | TEXT | FK to customers | Null rows dropped in staging |
| `product_id` | TEXT | FK to products | May be `None` in raw (injected); null rows dropped before staging |
| `quantity` | INTEGER | Number of units ordered | |
| `unit_price` | NUMERIC(12,2) | Price per unit at time of order | |
| `total_amount` | NUMERIC(12,2) | `quantity × unit_price` | May be `None` or negative in raw (injected); rows with null or ≤ 0 dropped before staging |
| `discount_amount` | NUMERIC(12,2) | Discount applied | |
| `net_amount` | NUMERIC(12,2) | `total_amount − discount_amount` | Computed in staging transformation only |
| `payment_method` | TEXT | Payment channel | Values: `credit_card`, `debit_card`, `bank_transfer`, `cash`, `mobile_pay` |
| `order_status` | TEXT | Order lifecycle status | Valid values: `completed`, `pending`, `cancelled`, `refunded`. May be `"unknown_status"` in raw (injected); rows outside the valid set dropped before staging |
| `region` | TEXT | Business region | Drawn from `settings.REGIONS`: `Mandera East`, `Mandera West`, `Mandera Central` |
| `order_date` | TEXT / TIMESTAMPTZ | Date and time of order | Cast to TIMESTAMPTZ in staging |
| `created_at` | TEXT | Record creation timestamp (source) | |
| `transformed_at` | TIMESTAMPTZ | Staging write timestamp | |
| `loaded_at` | TIMESTAMPTZ | PostgreSQL load timestamp | |

**Transformations applied (`transform_orders.py`):** drop rows with
null `order_id`, `customer_id`, or `product_id`; coerce `total_amount`
to numeric and drop rows that are null or ≤ 0; lowercase
`payment_method` and `order_status`; **drop rows where `order_status`
is outside the valid domain** (this specifically catches the
`invalid_status_rate` injected bad records); title-case `region`; cast
`order_date` to TIMESTAMPTZ; compute `net_amount`.

## monitoring.batch_row_counts

| Field | Type | Description |
|---|---|---|
| `id` | SERIAL | Surrogate key |
| `batch_id` | TEXT | Pipeline batch identifier |
| `entity` | TEXT | Logical entity name: `customers`, `products`, `orders` — **not** a physical table name |
| `mongo_count` | INTEGER | Records in MongoDB for this batch (via `settings.MONGO_COLLECTIONS`) |
| `raw_count` | INTEGER | Records in the corresponding `raw.*_raw` table |
| `staging_count` | INTEGER | Records written to the corresponding `staging.*_clean` table |
| `variance_pct` | NUMERIC | `(raw_count − staging_count) / raw_count`; default warning threshold: 5% |
| `status` | TEXT | `OK` or `WARN` |
| `recorded_at` | TIMESTAMPTZ | Timestamp of check |

## monitoring.data_quality_checks

| Field | Type | Description |
|---|---|---|
| `id` | SERIAL | Surrogate key |
| `batch_id` | TEXT | Pipeline batch identifier |
| `entity` | TEXT | Staging table checked (logical name) |
| `check_name` | TEXT | Name of the quality rule, e.g. `null_email`, `invalid_order_status` |
| `check_result` | TEXT | Supplementary detail (e.g. the valid value set for a domain check) |
| `failed_count` | INTEGER | Records that failed the check |
| `total_count` | INTEGER | Total records evaluated |
| `status` | TEXT | `PASS` or `FAIL` |
| `checked_at` | TIMESTAMPTZ | When check ran |

**Checks implemented (`validate_data_quality.py`):**

| Entity | Check name |
|---|---|
| All | `null_<entity>_id` |
| customers | `null_email`, `duplicate_email`, `missing_city` |
| products | `non_positive_unit_price`, `null_sku`, `null_product_name` |
| orders | `invalid_order_status`, `invalid_payment_method`, `non_positive_total_amount`, `negative_net_amount`, `null_product_id` |
